Convert README.txt to README.qmd

Your README.txt from Arc 2 is a snapshot — accurate the moment you wrote it, and silently out of date the moment your folder structure changes. Converting it to a .qmd file is our first step toward fixing that.

  1. Find README.txt in your project folder and rename it to README.qmd (right-click → Rename on Windows, or select the file and press Return on Mac)

  2. If you don’t already have a _quarto.yml file in your project root, create one and add:

    project:
  type: default

  3. In your README.qmd, wrap your existing file-structure listing in triple backticks (```) so it’s formatted as a code block

  4. In the terminal, run quarto render, then quarto preview readme.qmd

Note About This — What Is localhost?

The browser window that opens shows an address starting with localhost followed by a port number. That means your own computer is serving the file to itself — it is not on the internet, and no one else can see it. This is how you preview a Quarto document before it’s ever published anywhere.

Automate the Project Tree

Right now your file tree is still just text you typed — exactly as easy to go stale as it was in README.txt. This code chunk generates and annotates it automatically, every time you render, so it can’t.

Important Watch Out — This One’s Local-Only

dir_tree() reads your actual project folder from disk. There’s no real project structure to list inside a browser sandbox, so this chunk is shown as a display only — paste it into your own README.qmd to see it work.

#| echo: false
#| message: false
#| results: asis

library(fs)

tree_output <- capture.output(dir_tree(".", recurse = 2))

comments <- list(
  "raw_data"       = " (original data goes here)",
  "processed_data" = " (clean data goes here)",
  "scripts"        = " (code goes here)",
  "outputs"        = " (results and charts go here)",
  "README.qmd"     = " (project documentation)"
)

for (item in seq_along(tree_output)) {
  line <- tree_output[item]
  for (name in names(comments)) {
    if (grepl(name, line)) {
      tree_output[item] <- paste0(line, comments[[name]])
      break
    }
  }
}

cat("```\n")
cat(paste(tree_output, collapse = "\n"))
cat("\n```\n")
Note About This — What This Script Does
  • dir_tree() generates a visual tree of your project folder, two levels deep
  • capture.output() stores that tree as a character vector your own code can modify — rather than text you’d have to retype by hand
  • The comments list defines annotations for specific folders or files
  • The for loop (from Arc 3) checks each line against every name in that list and appends a matching annotation where it finds one
  • cat() prints the result back out as a formatted code block in your rendered document

Paste this chunk into your README.qmd in place of your plain file tree, wrapped in ```{r} instead of plain triple backticks. Re-render, and your README now regenerates its own project structure every time — try adding your own entry to the comments list and rendering again to see it reflected.

Your Turn: Visualize a Range, Safely

Modify the function below so it only plots when there’s actually data in the requested range — using an if/else from Arc 3 to check first.

Check your work 
visualize_range <- function(df, sample_col, min_val, max_val) {
  values <- df[[sample_col]]
  in_range <- values[values >= min_val & values <= max_val]

  if (length(in_range) == 0) {
    cat("No values found in that range\n")
  } else {
    hist(in_range, main = paste(sample_col, ":", min_val, "to", max_val),
         xlab = "Raw count")
  }
}

From Figure to Methods Text

Everything so far has been browser-based, which means the narrative text on this page can’t actually react to the live code cells above it — only a document you render yourself, on your own machine, can do that.

Important Watch Out — This Won’t Run on This Page

Inline code like `r min_val` only updates when you render a .qmd file locally. The live cells on this website are compiled once, ahead of time — changing a value in a browser cell above will never change a sentence of text on this page. Try the block below in your own analysis.qmd file instead, where it will.

Caution Code Tour — Tying Your Figure to Your Text

In your own .qmd file, a code chunk can set values that your narrative text then refers to directly:

#| echo: false

sample_col <- "GSM3119015"
min_val <- 10
max_val <- 1000

values <- raw_data[[sample_col]]
in_range_idx <- which(values >= min_val & values <= max_val)
## Methods

Raw counts for sample `r sample_col` were examined in the range
`r min_val`–`r max_val`. This range contained `r length(in_range_idx)`
genes (row indices: `r paste(head(in_range_idx, 5), collapse = ", ")`,
among others).

Change min_val and max_val in the code chunk, re-render, and watch both the sentence and the figure update together — from the same two numbers, in one place.

Note About This — Why Row Indices, Not Gene Names, for Now

We haven’t cleaned this dataset yet — that happens in Arc 5, which is where readable gene symbols get attached to each row. For now, a row index is a placeholder for “which gene,” standing in for the moment you’ll replace it with gene_symbol[in_range_idx] once that column exists. This is exactly the kind of methods-section sentence that, in a real paper, needs to update itself the instant an upstream analysis choice changes — which is the entire point of writing it this way instead of typing a number by hand.

Formatting as a journal submission — try this later, on your own machine. Quarto extensions can format a document to match a specific journal’s submission requirements — layout, fonts, figure formatting — without touching your analysis code at all. This part can’t run in a browser sandbox, since it installs files onto a real file system:

quarto add quarto-journals/plos
quarto use template quarto-journals/plos

This installs an extension that reformats your rendered output to PLOS journal standards. The same approach works for other journals under quarto-journals — the installation step changes, but your analysis code underneath never has to.

What We Did, and Why

What we built: converted a plain README into a self-updating Quarto document, created a figure inside a .qmd for the first time, wrote a function that safely checks before plotting, and read through a worked example of a methods-section sentence that updates itself from the same values driving a figure — plus a guided tour of a full publication-style analysis.

Why it matters: your project’s own documentation now regenerates itself instead of going stale, and the gap between “the number in my figure” and “the number in my methods text” — a classic, quiet source of irreproducible papers — disappears when both come from the same chunk of code instead of being typed twice, by hand, separately.
